# دليل النشر والتحقق الميداني الآمن على MikroTik RouterOS 7
> **AK Net HotSpot Captive Portal — RouterOS 7 & User Manager v7 Production Deployment Guide**

---

## ⚠️ تنبيهات أمان إلزامية قبل البدء (Mandatory Safety Rules)

1. **عدم التعديل العشوائي:** لا تقم بتنفيذ أي أوامر تعديلية على راوتر الإنتاج الفعلي دون أخذ نسخة احتياطية كاملة وتوثيق الإعدادات الحالية.
2. **عزل المراحل:** ينقسم هذا الدليل إلى ثلاث مراحل صارمة:
   - **المرحلة A (Stage A):** استعلام وفحص قراءة فقط (Read-Only) بنسبة 100%.
   - **المرحلة B (Stage B):** نشر آمن في مجلد مستقل واختبار دون المساس بالبوابة الحالية.
   - **المرحلة C (Stage C):** اختبار وتحقق تشغيلي حي مع مصفوفة معالجة المشاكل وتجهيز التراجع الفوري.
3. **عدم افتراض الأسماء الافتراضية:** لا تفترض أن بروفايل الهوتسبوت النشط اسمه `default` أو `hsprof1`، بل يجب استخراجه يدوياً عبر أوامر المرحلة A.

---

## المرحلة A: الفحص والاستعلام المسبق (Stage A — Read-Only Device Inspection)

> **جميع الأوامر في هذه المرحلة هي أوامر قراءة فقط (Read-Only) ولا تحدث أي تغيير على الراوتر.**

قم بالاتصال بالراوتر عبر WinBox أو SSH ونفذ الأوامر التالية في الـ Terminal:

### 1. التحقق من إصدار النظام وبنية العتاد:
```routeros
/system resource print
/system routerboard print
```
* **ماذا تفحص؟**
  - تأكد أن حقل `version` يبدأ بـ `7.` (مثل 7.12 أو 7.16 أو أحدث).
  - راجع نوع المعالج والبنية (`arm`, `arm64`, `tile`, `x86`, `mmips`).

### 2. تحديد خوادم HotSpot والبروفايل النشط:
```routeros
/ip hotspot print
/ip hotspot profile print detail
```
* **ماذا تفحص؟**
  - ابحث في `/ip hotspot print` عن الخادم النشط (`name`) والواجهة المرتبطة به (`interface`) وحقل `profile`.
  - في `/ip hotspot profile print detail`، ابحث عن البروفايل المرتبط وافحص:
    - حقل `html-directory`: هل هو `hotspot` أم `flash/hotspot`؟
    - حقل `login-by`: ما هي آليات الدخول المفعلة (`http-chap`, `http-pap`, `cookie`, `mac-cookie`)؟
    - حقل `use-radius`: هل هو `yes`؟
    - حقل `radius-interim-update`: ما هي مدة التحديث الدوري الحالية؟

### 3. فحص بنية التخزين والمجلدات:
```routeros
/file print where type="directory"
```
* **ماذا تفحص؟**
  - إذا ظهر مجلد باسم `flash`، فإن ذاكرة الجهاز تفصل التخزين الدائم، ومسار ملفات الهوتسبوت يجب أن يكون داخل `flash/` (مثل `flash/hotspot`).
  - إذا لم يوجد مجلد `flash` (مثل راوترات x86 أو CHR أو Cloud Core بدون فلاش منفصل)، يكون التخزين في المسار الجذري (مثل `hotspot`).

### 4. فحص تكوين خادم RADIUS:
```routeros
/radius print detail
/radius incoming print
```
* **ماذا تفحص؟**
  - تأكد من وجود إدخال بخدمة `service=hotspot`.
  - افحص عنوان الخادم `address` (غالباً `127.0.0.1` عند استخدام User Manager المحلي).
  - تحقق من تفعيل الـ CoA والطلبات الواردة في `/radius incoming print` (`accept=yes`).

### 5. فحص مجموعات وقيود User Manager v7:
```routeros
/user-manager/router print detail
/user-manager/user/group print detail
/user-manager/profile print detail
/user-manager/limitation print detail
/user-manager/profile-limitation print detail
```
* **ماذا تفحص؟**
  - أسماء المجموعات الحالية في حقل `name`.
  - ما هي السمات المحددة حالياً في `attributes` لكل مجموعة (مثل `Mikrotik-Total-Limit` أو `Session-Timeout`)؟
  - **تنبيه:** لا تقم بإعادة كتابة أو مسح المجموعات الموجودة! فقط وثق المسميات لمعرفة مطابقتها للباقات.

### 6. فحص الجلسات النشطة الحالية (Active HotSpot Sessions):
```routeros
/ip hotspot active print detail
```
* **ماذا تفحص؟**
  - انظر للمستخدمين المتصلين حالياً: ما هي الحقول المتوفرة؟
  - هل تظهر حقول `limit-bytes-total` أو `limit-bytes-out` أو `session-time-left`؟

## المرحلة B: النشر الآمن والتحكم بالتبديل (Stage B — Safe Deployment)

### الخطوة 1: إنشاء نسخة احتياطية كاملة (Full Backup & Export)
قبل إجراء أي تعديل، احفظ نسخة احتياطية من ملفات الراوتر وإعداداته:
```routeros
# إنشاء ملف نسخة احتياطية ثنائية مشفرة
/system backup save name="pre_hotspot_backup"

# تصدير ملف الإعدادات بصيغة نصية كاملة
/export file="pre_hotspot_config"
```
قم بسحب الملفين `pre_hotspot_backup.backup` و `pre_hotspot_config.rsc` إلى جهاز الكمبيوتر الخاص بك فوراً عبر WinBox.

### الخطوة 2: إنشاء مجلد مستقل للبوابة الجديدة
لا تقم بالكتابة فوق مجلد الهوتسبوت القديم، بل أنشئ مجلداً جديداً موازياً له:
- **في الأجهزة ذات الفلاش:** أنشئ مجلداً باسم `flash/hotspot_v2`
- **في الأجهزة ذات القرص المباشر:** أنشئ مجلداً باسم `hotspot_v2`

### الخطوة 3: رفع ملفات البوابة المعتمدة
ارفع ملفات البوابة التالية فقط إلى المجلد الجديد (`hotspot_v2`):
- `login.html`
- `status.html`
- `logout.html`
- `alogin.html`
- `error.html`
- `locked.html`
- `radvert.html`
- `redirect.html`
- `rlogin.html`
- `md5.js`
- `api.json`
- `errors.txt`
- `favicon.ico`
- مجلد `css/`
- مجلد `img/`
- مجلد `xml/`

> ⛔ **استثناء أمني:** لا تقم برفع مجلد `test/` أو مجلد `dev/` أو ملفات `.git` أو ملفات `.md` إلى الراوتر، لتوفير مساحة الذاكرة ومنع كشف أي أدوات تطويرية للمشتركين.

### الخطوة 4: التحقق من اكتمال الملفات المرفوعة:
```routeros
/file print where name~"hotspot_v2"
```
تأكد من وجود جميع صفحات الـ HTML وأحجامها المتطابقة.

### الخطوة 5: التحويل التدريجي والمضبوط للبروفايل
> ⚠️ **أمر تعديل إعدادات [CONFIGURATION CHANGING COMMAND]**  
> استبدل `<ACTIVE_PROFILE_NAME>` باسم البروفايل الفعلي المستخرج من المرحلة A.  
> استبدل `<NEW_DIR>` بـ `hotspot_v2` أو `flash/hotspot_v2`.

```routeros
/ip hotspot profile set [find name="<ACTIVE_PROFILE_NAME>"] html-directory="<NEW_DIR>"
```

### الخطوة 6: إجراءات التراجع الفوري في حال الطوارئ (Rollback)
إذا واجهت أي خلل تشغيلي غير متوقع أثناء التجربة، ارجع لمجلد الهوتسبوت الأصلي فوراً بتنفيذ:
```routeros
# أمر التراجع الفوري للبوابة القديمة
/ip hotspot profile set [find name="<ACTIVE_PROFILE_NAME>"] html-directory="<ORIGINAL_HOTSPOT_DIR>"
```

## المرحلة C: التحقق التشغيلي الحي والميداني (Stage C — Live Verification)

بعد تبديل المسار في الخطوة 5، اتصل بشبكة الواي فاي من هاتف ذكي أو كمبيوتر محمول وقم بتنفيذ الاختبارات التالية:

### 1. قائمة التحقق الميدانية:
- [ ] **ظهور صفحة تسجيل الدخول (`login.html`):** تحميل سريع، الشعار متناسق، لا توجد نصوص إنجليزية مكسورة، خيارات الاتصال تعمل.
- [ ] **المصادقة ونجاح الدخول:** تسجيل الدخول بكرت تجريبي يعمل بنجاح بدون تأخير.
- [ ] **التوجيه إلى صفحة الحالة (`status.html`):** الانتقال التلقائي عبر `alogin.html` إلى صفحة الحالة.
- [ ] **بيانات المستخدم:** ظهور اسم المستخدم (`username`) وعنوان IP وعنوان MAC بشكل صحيح ودقيق.
- [ ] **استهلاك الجلسة الحالية:** يظهر حجم الرفع والتنزيل الفعلي للجلسة مع تحديث العدادات.
- [ ] **عداد مدة الاتصال (Uptime):** يتقدم ثانية بثانية (`00:01`, `00:02`, ...) بشكل حي.
- [ ] **الرصيد المتبقي:** 
  - في حال تفعيل سمة الرصيد في اليوزر مانجر: ظهور الحصة المتبقية بدقة.
  - في حال اعتماد التتبع على السيرفر: ظهور "يُدار عبر السيرفر" دون تزييف أو طرح استهلاك الجلسة الواحدة.
- [ ] **شريط التقدم:** يعمل بسلاسة فقط عند توفر السعة والرصيد المتبقي الحقيقي.
- [ ] **نافذة التفاصيل المنبثقة:** تفتح دون خطأ، وتظهر تفاصيل الكرت كاملة.
- [ ] **تسجيل الخروج (`logout.html`):** عند النقر على "تسجيل الخروج" يتم إنهاء الجلسة وظهور ملخص الاستهلاك مع إمكانية تسجيل دخول جديد.

## مصفوفة معالجة المشكلات التشغيلية (Troubleshooting Matrix)

| العَرَض الملاحظ | السبب المحتمل | إجراء المعالجة الميداني |
| :--- | :--- | :--- |
| **الرصيد يظهر "يُدار عبر السيرفر"** | لم يتم تمرير السمة `Mikrotik-Total-Limit` في مجموعة المستخدم في User Manager v7 | افتح User Manager وتأكد من كتابة سمة `Mikrotik-Total-Limit=<bytes>` في مجموعة الكرت المعنية. |
| **الوقت يظهر "صلاحية الباقة: X" دون عد تنازلي** | لم يتم تمرير سمة `Session-Timeout` للجلسة عبر RADIUS | إذا أردت فصل الجلسة زمنياً بعد مدة محددة، اضف `Session-Timeout=<seconds>` في سمات المجموعة. إذا أردت الجلسة مفتوحة مع متابعة الصلاحية التقويمية بالسيرفر، فهذا السلوك صحيح تماماً. |
| **ظهور خطأ 404 عند النقر على رابط User Manager** | عدم وجود الشرطة المائلة الختامية `/` | تم تصحيح الرابط برمجياً في البوابة إلى `http://$(hostname)/um/`، تأكد أن خدمة الـ User Manager مفعلة على المنفذ الافتراضي للراوتر. |
| **تكرار طلب تسجيل الدخول عند قفل الشاشة في الهواتف** | مهلة عدم النشاط (Idle Timeout) قصيرة جداً أو عدم تفعيل الكوكيز | في بروفايل الهوتسبوت، فعل خيار `cookie` و `mac-cookie` لضمان استمرار اتصال المستخدم. |
| **الرصيد يظهر كقيمة سالبة أو مكسورة في باقات 40GB+** | إرسال سعات تتجاوز 4GB كعدد 32-bit دون تفعيل الـ Gigawords | استخدم الصيغة الصحيحة للـ Gigawords الموضحة في دليل التكوين: `Mikrotik-Total-Limit-Gigawords=<multiplier>` لحساب الباقات الضخمة. |

## المعلومات الإلزامية المطلوب جمعها قبل أي تعديل على إعدادات الراوتر

إذا واجهت أي اختلاف في النتائج بين بيئة الاختبار والميدان، قم بنسخ مخرجات هذه الأوامر وأرسلها للمطور دون تغيير:
```routeros
/ip hotspot active print detail
/ip hotspot profile print detail
/radius print detail
/user-manager/user/group print detail
/log print where topics~"hotspot"
```
هذه البيانات تتيح تشخيص سلوك الراوتر والـ RADIUS بدقة تامة دون تخمين.
